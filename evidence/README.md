# Evidence — Audit Trail for Reproducibility and Trustworthiness

## Overview
This folder contains the key audit reports generated by the Gate
and Docs scripts throughout the data processing pipeline. These
reports serve as hard evidence that every critical data processing
decision is (1) explicitly validated by automated checks, and
(2) traceable to its root cause.

The evidence is organised into six categories, each corresponding
to a critical dimension of data trustworthiness.

## Evidence Categories

### 1. Leakage Audit (`leakage_audit/`)
**One-vote veto**. Proves that no answer column, future-information
column, or intermediate label column has leaked into the 48 processed
model-input tables.
- `step3k_leakage_audit_v2.txt` — PASS report for all 48 tables

### 2. Fit Domain Audit (`fit_domain_audit/`)
**One-vote veto**. Proves that all imputation, clipping, and scaling
parameters are fitted strictly on the training split (train ∩
label_valid_H8h domain).
- `step3k2_fit_domain_audit_v2.txt` — PASS report with SHA256 hashes

### 3. Time Order QC (`time_order_qc/`)
**One-vote veto**. Proves that the time axis is consistent within
each machine — no duplicate keys, no time reversal, no
time_slice / slice_last_time_us mismatch. This is the prerequisite
for the searchsorted / next-fail label algorithm.
- `step2e_time_order_qc_summary_v2.txt` — dup=0, mismatch=0, no reversal

### 4. Label QC (`label_qc/`)
**One-vote veto**. Proves that all labels are correctly generated:
FAIL-moment slices are excluded, right-censored slices are excluded,
and no unexplained NaN samples remain (nan_other=0).
- `step2d_label_qc_report_v2.txt` — NaN decomposition and sanity checks

### 5. Split Diagnostics (`split_diagnostics/`)
Provides post-hoc diagnostics of the train / val / test split
without influencing the split decision. Reports slice count
distributions, fail-machine rates, and other descriptive statistics.
- `step2b_split_diagnostics_v2.txt`

### 6. Feature Diagnostics (`feature_diagnostics/`)
Characterises the feature space: sparse / constant columns, and the
association between CPU-distribution missingness and failure risk.
- `step3e1_sparse_constant_summary_v2.csv`
- `step3g_cpu_dist_missing_vs_label_H8h_v2.csv`

## How to Use
Each subfolder contains a standalone report. For a complete
narrative of the evidence chain, see the pipeline summary generated
by `Step0_stage1_3_summary_report_v2.py`.
